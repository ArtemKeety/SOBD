# Сводка: методы, действия и логика анализа Delivery ETA

Два ноутбука делают одну работу по частям.

1. `1_Data_cleansing.ipynb` читает `delivery_eta.parquet` из HDFS, проверяет типы и плохие числа, сохраняет таблицу Iceberg `spark_catalog.delivery_eta_database.sobd_lab1_delivery_eta`.
2. `2_Exploratory_analysis.ipynb` читает эту таблицу, чистит строки и пропуски, считает статистики, строит графики и корреляции, сохраняет `sobd_lab1_delivery_eta_processed`.

Каждая строка — один потенциальный заказ. Цель — `delivery_eta_minutes`, время прибытия курьера в минутах.

Модели здесь не обучаются. Результат — очищенная таблица и разведочный анализ.

---

## 1. Трансформация и действие

В Spark вызов бывает двух видов.

**Трансформация** описывает, что сделать с таблицей, и возвращает новый датафрейм. Данные при этом ещё не читаются. Spark только дописывает шаг в план.

**Действие** требует результат: число, строки на экран, запись на диск, квантили, корреляцию. Только действие запускает план. До него цепочка `filter` / `select` / `withColumn` ничего не считает.

Один и тот же план может выполниться несколько раз, если после него стоит несколько действий. В ноутбуках это сделано специально: отдельные `count()` и `show()` показывают причину каждого удаления, но каждый такой вызов заново читает данные.

Пример из второй части:

```python
df = df.filter(F.col(target_col).isNotNull())  # трансформация, расчёта нет
df = df.filter(F.col(target_col) >= 0)         # ещё одна трансформация
valid_rows = df.count()                         # действие: план выполняется
```

`groupBy(...).count()` — не то же самое, что `df.count()`. После `groupBy` метод `count()` возвращает новую таблицу частот. Это трансформация. Запуск происходит позже, на `show()` или `collect()`.

## 2. Какие вызовы что делают

### Действия — здесь начинается расчёт

| Метод | Что возвращает | Где используется |
|---|---|---|
| `show()` | печатает строки | просмотр фрагмента, частот, схемы значений |
| `count()` у датафрейма | число строк | сколько заказов, сколько плохих значений, сколько удалили |
| `first()` | одну строку результата | минимум, максимум, мода, сумма размеров файлов |
| `collect()` | список строк на драйвер | точки для графика: корзины гистограммы, частоты категорий, дни |
| `approxQuantile(col, probs, error)` | список квантилей | Q1, медиана, Q3, P95 и медиана для заполнения пропусков |
| `stat.corr(a, b)` | одно число, корреляция Пирсона | связь `num_*` с целью и матрица выбранных признаков |
| `writeTo(...).using("iceberg").createOrReplace()` | записывает таблицу | сохранение после части 1 и после очистки |
| `spark.sql("CREATE DATABASE ...")` | команда каталога | создать базу, если её нет |
| `spark.sql("SHOW TABLES ...").show()` | список таблиц | проверка, что таблица появилась |
| `printSchema()` | печатает имена и типы | схема до и после подготовки |
| `spark.stop()` | останавливает приложение | освободить ресурсы YARN в конце |

`printSchema()` берёт уже известную схему и полный проход по строкам не делает.

`first()` и `collect()` привозят данные на драйвер. Поэтому на драйвер попадают сводки: десятки корзин гистограммы, не больше 100 точек выброса, не больше 15 категорий, не больше 366 дней. Вся таблица на драйвер не собирается.

### Трансформации — план без запуска

| Метод | Что делает |
|---|---|
| `spark.read.parquet(path)` | план чтения Parquet из HDFS |
| `spark.table(name)` | план чтения таблицы Iceberg |
| `select(...)` | оставить или собрать указанные столбцы |
| `filter(...)` | оставить строки, где условие истинно |
| `withColumn(name, expr)` | добавить или заменить один столбец |
| `drop(column)` | убрать столбец, строки не трогает |
| `fillna({column: value})` | подставить значение вместо NULL в одном столбце |
| `groupBy(...)` | сгруппировать одинаковые значения |
| `agg(...)` | посчитать несколько агрегатов одним проходом |
| `orderBy(...)` | задать порядок строк результата |
| `limit(n)` | взять не больше n строк |
| `describe()` | план сводки: count, mean, stddev, min, max |
| `groupBy(...).count()` | план таблицы «значение → сколько раз встретилось» |

### Функции столбца `F.*`

Они не запускают расчёт сами. Это формулы внутри `select`, `filter`, `agg`, `withColumn`.

| Функция | Смысл |
|---|---|
| `F.col("имя")` | ссылка на столбец |
| `F.when(условие, значение)` | если условие верно — значение, иначе NULL, если `otherwise` не задан |
| `F.otherwise(значение)` | ветка «во всех остальных случаях» |
| `F.alias("имя")` | имя столбца в результате |
| `F.isnan(value)` | ячейка равна NaN («не число»), это не то же самое, что NULL |
| `value.isin(0, 1)` | значение входит в список |
| `isNull()` / `isNotNull()` | пропуск или заполненная ячейка |
| `cast("long")` | привести тип; здесь булево «это NULL» превращается в 0 или 1 для суммы |
| `F.count(...)` | сколько непустых результатов попало в агрегат |
| `F.count("*")` | сколько строк в группе |
| `F.sum(...)` | сумма |
| `F.min` / `F.max` / `F.mean` | минимум, максимум, среднее |
| `F.floor(...)` | целая часть; номер корзины гистограммы |
| `F.to_timestamp` | строка ISO → тип timestamp |
| `F.to_date` | дата без времени |
| `F.hour` | час от 0 до 23 |
| `F.desc` / `F.asc` | сортировка по убыванию и по возрастанию |

## 3. Логика целиком

```text
HDFS: delivery_eta.parquet
        |
        |  часть 1: типы, NaN, бесконечности, бинарные значения
        v
Iceberg: sobd_lab1_delivery_eta
        |
        |  часть 2: плохие строки, выбросы цели, пропуски, графики
        v
Iceberg: sobd_lab1_delivery_eta_processed
        |
        v
проверка размера файлов данных > 1 ГиБ
```

Порядок во второй части важен.

1. Сначала убираются строки с пустой целью, отрицательным временем и пустым `timestamp`. Цель не заполняется медианой: иначе в ответ подставляется выдуманное время.
2. Потом считается IQR уже по оставшейся цели и отрезаются хвосты.
3. Доли пропусков в `num_*` считаются после удаления строк. Порог 50% применяется к этой доле.
4. Медиана для заполнения берётся по оставшимся наблюдаемым значениям.
5. Корреляция считается уже после фильтра и заполнения. Заполнение медианой само может усилить или ослабить связь.

Исходная таблица части 1 не перезаписывается. Очищенный результат лежит в отдельной таблице.

## 4. Часть 1 — что происходит по шагам

### Сессия

`create_spark_configuration()` собирает `SparkConf`.

- `setAppName` — имя в Spark UI и YARN.
- `setMaster("yarn")` — ресурсы выдаёт YARN.
- `deployMode = client` — драйвер живёт в процессе ноутбука, задачи считают исполнители на кластере.
- 2 исполнителя, по 8 ядер и 12 ГБ; драйвер — 2 ядра и 4 ГБ.
- пакет Iceberg 1.6.0, каталог `spark_catalog` типа Hadoop, склад `hdfs:///user/<user>/warehouse`.

`SparkSession.builder.config(conf=conf).getOrCreate()` создаёт сессию или берёт уже открытую. Старая сессия может сохранить прежние настройки, поэтому при смене конфигурации ядро перезапускают.

`os.getenv("USER")` подставляет имя пользователя в путь HDFS. Чужой путь копировать не нужно.

### Чтение и группы столбцов

`spark.read.parquet(path)` читает Parquet. Имена и типы уже лежат в файле, схему вручную не задаём.

Дальше столбцы раскладываются по префиксу имени:

- `num_*` — 221 числовой признак;
- `bin_*` — бинарный признак;
- `cat_*` — коды категорий;
- `timestamp` и `delivery_eta_minutes` — отдельно.

`select(preview_cols).show(5)` показывает 5 строк только выбранных столбцов. В таблице при этом остаются все 227.

Если `timestamp` имеет тип `string`, `withColumn` + `F.to_timestamp` переводит его во время. Числовые и категориальные столбцы здесь не меняются.

### Проверка бинарного столбца

Для каждого `bin_*`:

1. `groupBy(column).count().orderBy(column).show()` — какие значения есть и как часто.
2. `filter(isNotNull())` убирает пропуски: NULL не считается запрещённым значением.
3. Два фильтра подряд оставляют только то, что не равно ни 0, ни 1.
4. `count()` — сколько таких ячеек.

Если счётчик больше нуля, столбец попадает в `binary_problem_cols`.

### Проверка NaN и бесконечностей

Для всех `num_*` и цели одним `agg` считаются три вещи: число NaN, число `+inf`, число `-inf`.

`F.count(F.when(F.isnan(value), 1))` считает только строки, где `when` что-то вернул. Обычные числа и NULL в этот счётчик не входят.

Один `agg` на все столбцы читает таблицу один раз. Отдельный `count()` на каждый столбец делал бы сотни проходов.

Столбцы с ненулевым счётчиком попадают в `numeric_problem_cols`.

### Что меняет `transform_dataframe`

Функция проходит по столбцам и собирает один `select`.

- Проблемный числовой столбец: `when` оставляет число, только если это не NaN и не бесконечность. Иначе получается NULL. Тип столбца остаётся.
- Проблемный бинарный столбец: `when(value.isin(0, 1), value)` оставляет 0 и 1, остальное становится NULL.
- Остальные столбцы передаются как есть.

Один `select` вместо сотен `withColumn`: план строится один раз.

Если проверка ничего плохого не нашла, списки проблем пустые и функция возвращает те же столбцы без замен.

Обычные NULL здесь не заполняются. Их разбирает вторая часть.

### Контроль и запись

После преобразования считаются:

- `df.count()` — число строк;
- `F.min` / `F.max` по времени и по цели;
- число отрицательных ETA, пропусков цели и пропусков `timestamp`.

Эти строки в части 1 не удаляются. Подсчёт только фиксирует, что в данных есть.

Дальше:

```python
spark.sql("CREATE DATABASE IF NOT EXISTS ...")
spark.catalog.setCurrentDatabase(database_name)
df.writeTo(full_table_name).using("iceberg").createOrReplace()
```

`createOrReplace()` создаёт таблицу или полностью заменяет её. Это действие: здесь план части 1 реально выполняется и пишется в HDFS.

Проверка: `SHOW TABLES`, затем `spark.table(...).select(...).show(5)`.

## 5. Часть 2 — что происходит по шагам

Сессия такая же. Меняется только имя приложения. Читается таблица части 1: `spark.table(source_table)`.

Три константы — правила этой работы, не свойства доставки.

| Параметр | Значение | На что влияет |
|---|---|---|
| `missing_threshold` | 0.50 | столбец `num_*` удаляется, если пропусков строго больше половины строк |
| `top_features_count` | 5 | сколько числовых признаков подробно рисовать |
| `top_categories_count` | 15 | сколько категорий показывать на рисунке |

Порог 50% меняет состав столбцов. Числа 5 и 15 ограничивают только картинки: остальные столбцы и строки в расчётах остаются.

### Пропуски до очистки

`missing_summary` для каждого столбца считает `F.sum(isNull().cast("long"))` одним `agg`. Сумма нулей и единиц равна числу пропусков. Печатаются только столбцы, где пропуски есть.

### Плохие строки

По порядку:

1. Показать до 10 строк с `delivery_eta_minutes < 0` и посчитать их.
2. Посчитать строки с пустой целью.
3. Оставить строки, где цель не NULL и цель `>= 0`.
4. Посчитать строки с пустым `timestamp` уже среди оставшихся.
5. Оставить строки с заполненным временем.
6. `count()` — сколько строк осталось.

Нулевое время не удаляется: из описания датасета не следует, что 0 — ошибка.

Отрицательные строки входят и в показ, и в фильтр `>= 0`. В итоговом отчёте отрицательные и «строки без цели» печатаются отдельно. Это разные причины, даже если одна строка теоретически могла бы попасть в оба списка до фильтра.

### Статистика столбца

`column_statistics`:

- `select(column).describe().show()` — count, mean, stddev, min, max по непустым значениям;
- `approxQuantile(..., [0.25, 0.50, 0.75, 0.95], 0.001)` — Q1, медиана, Q3, P95.

Последний аргумент `0.001` — допустимая относительная ошибка по рангу, а не ошибка в минутах. Квантиль приближённый. Пустой столбец функцию не ломает: если список квантилей короче четырёх, словарь статистик остаётся пустым.

### Гистограмма

`plot_histogram` не тащит все заказы в Python.

1. Берутся непустые значения, их min и max.
2. Диапазон делится на 50 корзин равной ширины.
3. `floor((значение - min) / ширина)` даёт номер корзины.
4. Значение, попавшее ровно в правый край, сдвигается в последнюю корзину через `when ... otherwise`.
5. `groupBy("histogram_bucket").count()` считает частоты.
6. `collect()` привозит на драйвер не больше 50 строк.
7. Matplotlib рисует центры корзин.

Если min равен max, рисуется один столбик: у постоянного признака ширины интервала нет.

### Ящик с усами

Границы: `Q1 - 1.5 * IQR` и `Q3 + 1.5 * IQR`, где `IQR = Q3 - Q1`.

Усы — это не сами границы, а фактические min и max среди значений внутри границ.

Точки за границами: `filter` + `limit(50)` снизу и сверху, затем `collect()`. На рисунке не больше 100 точек. Это иллюстрация, не полный список выбросов и не случайная выборка.

`ax.bxp([box])` рисует ящик из уже посчитанных чисел: q1, медиана, q3, концы усов, точки.

### Удаление выбросов цели

Правило применяется только к `delivery_eta_minutes`.

- Если IQR равен 0, фильтр не делается: квартили не задают диапазон.
- Нижняя граница не опускается ниже 0, потому что отрицательное время уже убрано и время прибытия не бывает отрицательным.
- Сначала считаются строки ниже и выше границ, потом два `filter` оставляют интервал включительно.

К `num_*` это правило не применяется: признаки обезличены и стандартизованы, знак и величина сами по себе не говорят об ошибке. Коды `cat_*` не являются непрерывными числами, выбросы по ним не ищутся.

После фильтра статистики, гистограмма и ящик строятся заново, чтобы было видно, как изменилась цель.

Долгая доставка может быть настоящей. Фильтр ограничивает хвост распределения, он не доказывает, что удалённые заказы ошибочны.

### Пропуски в `num_*`

Доли считаются заново, уже от числа строк после IQR.

- Доля **больше** 0.50 — `drop(column)`. Столбец удаляется, заказы остаются.
- Иначе столбец сохраняется. Если пропуски есть, медиана берётся `approxQuantile(..., [0.5], 0.001)` по непустым значениям и подставляется через `fillna`.

Медиана выбрана потому, что длинный хвост сдвигает среднее сильнее, чем середину. После заполнения у медианы может появиться лишний пик: много пропусков стали одним и тем же числом.

Число строк при `fillna` не меняется.

### Пропуски в `bin_*` и `cat_*`

Среднее по коду категории не считается: код «3» не означает величину.

- Если непустых значений нет, столбец удаляется. Моду взять не из чего.
- Иначе мода — самое частое значение: `groupBy.count().orderBy(F.desc("count"), F.asc(column)).first()`.
- При равной частоте побеждает меньший код. Так результат не зависит от порядка файлов.
- Пропуски заполняются этой модой через `fillna`.

Затем `missing_summary` проверяет, что пропусков не осталось. Сумма по всем столбцам печатается как `remaining_missing`.

### Корреляция и отбор картинок

Для каждого оставшегося `num_*`:

```python
df.stat.corr(column, target_col)
```

Это коэффициент Пирсона: линейная связь. Знак — направление, модуль — сила. Постоянный столбец даёт нечисло (`NaN`), `math.isfinite` такие пары отбрасывает.

Список сортируется по модулю. Первые 5 имён идут в `important_num_cols`. Для них снова считаются статистики, гистограмма и ящик.

Пять признаков — это отбор для показа. Остальные `num_*` в таблице остаются. Большая корреляция не называет скрытый смысл признака и не доказывает причину.

Категории в Пирсон не входят.

### Категории и время

`plot_category`:

- частоты через `groupBy.count()`;
- для категорий порядок по убыванию частоты, при равенстве — по возрастанию кода;
- на драйвер `limit(top_n).collect()`;
- для каждой показанной категории отдельный `filter` и `F.mean` по цели.

Среднее по редкой категории неустойчиво: его сильнее двигает несколько заказов.

Для времени создаётся временная таблица, не итоговая:

- `F.to_date` — календарный день;
- `F.hour` — час суток;
- `groupBy("observation_date").agg(count, mean)` — заказы и среднее ETA за день;
- `orderBy(desc).limit(366)` — не больше последних 366 дат в результате сортировки по убыванию;
- `reverse()` разворачивает их слева направо, от ранних к поздним.

Часы рисуются все, до 24, в календарном порядке (`sort_by_value=True`). Часовой пояс не назначается: час берётся из значения timestamp как оно записано.

Столбцы `observation_date` и `observation_hour` в сохраняемую таблицу не попадают. Они живут только в `time_data`.

### Матрица

По выбранным `num_*` плюс цель считаются все пары `stat.corr`. На рисунке шкала от −1 до 1. Если корреляция нечисловая, в клетке стоит прочерк.

Диагональ — корреляция столбца с самим собой, она равна 1, когда столбец не постоянный.

### Сохранение и размер

Печатается баланс: сколько строк было, сколько снято по каждой причине, сколько столбцов удалено, сколько пропусков осталось.

`df.writeTo(processed_table).using("iceberg").createOrReplace()` пишет очищенную таблицу.

Размер проверяется не по числу строк и не по исходному файлу. Сжатие Parquet его меняет.

```python
spark.table(processed_table + ".files")
```

Это служебная таблица Iceberg. `content == 0` — файл данных. `F.sum("file_size_in_bytes")` складывает размеры текущего состояния, без старых снимков и без умножения на реплики HDFS.

Порог в коде — 1 ГиБ = 1024³ байт. Условие строгое: размер должен быть **больше** этого числа.

## 7. Где какое действие стоит в цепочке

Часть 1, по порядку запуска расчёта:

1. `show()` — первый взгляд на Parquet.
2. `select.show()` — фрагмент нужных столбцов.
3. `printSchema()`.
4. Для бинарных столбцов: `show()` частот, затем `count()` недопустимых значений.
5. `agg(...).first()` — все NaN и бесконечности.
6. `count()`, четыре раза `select(min/max).first()`, три `filter.count()` — размер, период, диапазон цели, проблемы строк.
7. `writeTo.createOrReplace()` — запись Iceberg.
8. `SHOW TABLES`, `spark.table`, `show()`.

Часть 2:

1. `printSchema()`, `show()`, `count()` — что прочитали.
2. `agg.first()` — пропуски до очистки.
3. `show()` и `count()` отрицательных ETA; `count()` пустой цели; после фильтров `count()` пустого времени и оставшихся строк.
4. `describe().show()` и `approxQuantile` по цели.
5. Для гистограммы: `min`/`max` через `first()`, затем `collect()` корзин.
6. Для ящика: `min`/`max` усов через `first()`, `collect()` точек.
7. Два `count()` хвостов IQR, фильтр, `count()` оставшихся строк, повтор статистик и рисунков.
8. Снова пропуски. Для удаляемых `num_*` — только `drop`. Для заполняемых — `approxQuantile` медианы и `fillna`.
9. Для дискретных столбцов: `count()` непустых, при пропусках `groupBy.count().first()` как мода, `fillna`.
10. Контрольный подсчёт пропусков.
11. `stat.corr` по каждому оставшемуся `num_*`.
12. Статистики и рисунки пяти признаков.
13. Частоты категорий: `show`, `collect`, затем `mean` по каждой показанной категории.
14. Агрегат по дням: `collect` не больше 366 строк. Часы — тем же `plot_category`.
15. Матрица `stat.corr`.
16. Итоговый `count()`, запись Iceberg, `count()` и `printSchema()` прочитанной таблицы.
17. `sum(file_size_in_bytes).first()` — размер.

## 8. Что говорить своими словами

Загрузка в HDFS делается в терминале один раз: `hdfs dfs -copyFromLocal`. Ноутбуки файл с локального диска сами не копируют. Часть 1 читает уже лежащий Parquet. Часть 2 читает таблицу Iceberg, а не исходный Parquet.

Parquet хранит схему. Iceberg добавляет таблицу в каталоге: имя, историю, список файлов. `createOrReplace` заменяет содержимое таблицы целиком.

`NULL` — значения нет. `NaN` — в ячейке записано «не число». Бесконечность — тоже не обычное измерение. Часть 1 переводит NaN и бесконечности в NULL, чтобы часть 2 видела их как пропуски. Сами пропуски часть 1 не заполняет.

Цель и время не восстанавливаются. Нет ответа или нет момента заказа — строка не используется. Числовой пропуск в признаке заполняется медианой, кодовый — модой.

Выбросы ищутся только у цели и только правилом полуторного IQR. Удаление столбца с большой долей пропусков не удаляет заказы. Удаление плохой строки не удаляет остальные признаки этой строки из словаря столбцов: строка уходит целиком.

Корреляция считается после этих решений, поэтому она описывает очищенную таблицу. Она не восстанавливает название обезличенного `num_*` и не показывает причину, почему курьер ехал дольше.

Графики считают на кластере частоты и квантили. На ноутбук приезжает короткая сводка.
